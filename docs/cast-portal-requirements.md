# キャストポータルと売上ダッシュボード — 要件書

作成: 2026-09-17 ／ 判断: 高野 ／ 状態: 確定（実装着手）

## 0. 目的

1. 店長が、店舗別の日次売上（来店 / 遠隔）を管理画面で追える
2. キャスト本人がログインして、自分の報酬（確定前の速報を含む）を見られる
3. キャスト全員が、キャストごとの月別売上を見られる

## 1. 前提と方針（代表判断 2026-09-17）

| # | 論点 | 決定 |
|---|---|---|
| 1 | キャスト向けの語と内訳 | **「報酬」**と呼び、内訳は**「稼働報酬」「売上連動報酬」の2本**。時給・労働時間・基本給・通勤手当・バック率・最低賃金は**キャスト向けに一切出さない**（全員業務委託。時間×時給の内訳は労働者性の徴表になるため） |
| 2 | 確定前の明細 | **速報として見せる**。店長が「確定」を押した期間だけ「確定」と表示し、以後は保存値が変わらない |
| 3 | 全員向けの売上一覧 | 来店 / 遠隔の**内訳まで出す**。報酬・率は出さない。**→ 2026-09-18 変更: キャスト別売上はオーナーのみ**（権限管理で店長・キャストに付けることはできる） |
| 4 | 遠隔の日次集計 | **キャストの所属店舗**で集計する（給与計算と同じ基準。remodri の `groupBy=date&storeCode=` がこの基準） |
| 5 | 招待の起点 | 管理画面のキャストマスタから店長がメールアドレスを入力して送る |

契約書の報酬条項と画面の表示が一致しているかは、別途税理士/社労士に確認する（本要件の範囲外）。

## 2. ロールと認可

- `User.role` に **`CAST`** を追加（既存: `CUSTOMER` / `ADMIN`）
- `Cast.userId`（nullable, unique）でキャストとユーザーを 1:1 に結ぶ
- キャストの画面は `/cast/me/*`。**サーバー側で `session.userId → Cast` を引いて固定**し、URL やリクエストに他人の castId を入れても取れない
- `CAST` は `/admin` に入れない。`CUSTOMER` / `ADMIN` は `/cast/me` に入れない（ADMIN の代理閲覧は今は作らない）
- 客（CUSTOMER）と同じメールアドレスでは招待を受けられない（購入履歴・ポイントと混ぜない）。別のメールを使う

## 3. 招待

> **2026-09-18 変更**: 初期パスワード方式に置き換えた（`docs/roles-and-permissions.md`）。以下はそれ以前の設計。

- キャストマスタの行に「招待」ボタン → メールアドレス入力 → `CastInviteToken`（castId, email, tokenHash, expiresAt=7日, usedAt）を作り、Resend で招待メールを送る
- リンク `/cast/invite/[token]` → パスワード設定 → `User(role=CAST, emailVerified=true)` を作成し `Cast.userId` に結ぶ → `/cast/me` へ
- 既に結ばれているキャストは再招待不可（解除は管理画面から `userId` を外す操作を別途）。既存ユーザーのメールなら拒否
- トークンは SHA-256 のハッシュで保存。1回使ったら `usedAt`。期限切れ・使用済み・不正は同じ文言で拒否

## 4. 報酬（キャスト本人のみ）`/cast/me/rewards`

### 4-1. 表示

月ごとに1行（当月＋過去12ヶ月）。

| 列 | 内容 |
|---|---|
| 月 | 2026/09 |
| 状態 | **確定** / **速報**（「まだ変わることがあります」を添える） |
| 稼働報酬 | 合計 − 売上連動報酬 |
| 売上連動報酬 | バック（back） |
| 合計 | 支払額（100円丸め後） |

半月（前半/後半）は内部の単位であり、キャストには**月で1行**に畳んで見せる。展開すれば前半/後半も見られる。

出さないもの: 時給・労働時間・基本給・通勤手当・バック率・最低賃金・他人の報酬。

### 4-2. 値の出どころ

| 期間の状態 | 出どころ |
|---|---|
| 確定済み（`SalaryPeriod.finalizedAt` あり） | 保存済み `SalaryCastRecord`（不変） |
| 保存済みだが未確定 | 保存済みレコード（店長の最新計算）。状態は「速報」 |
| 保存が無い | **ライブ計算**（Airレジ取込＋remodri＋みせ勤打刻をランク時給で）。状態は「速報」。Airレジは前日まで、みせ勤に打刻が無い日は稼働報酬が載らない旨を注記 |

ライブ計算は店舗×期間で行い（既存の計算エンジンをそのまま使う）、本人の行だけ返す。結果は 10 分メモリキャッシュ。取り込み漏れや退勤打刻なしで計算が止まる場合は、その期間を「集計中」と表示して額を出さない（誤った額を見せない）。

## 5. 確定（店長）

- `SalaryPeriod` に `finalizedAt` / `finalizedByUserId` を追加
- 給与履歴の各行に「確定」ボタン。確定すると「計算実行＋DB保存」で同じ期間を上書きできない（409）
- 「確定を解除」は別ボタン＋確認ダイアログ。解除・確定は `SalaryPeriodLog`（periodId, action, userId, createdAt）に残す
- 確定はキャスト向け表示の「確定」ラベルの根拠であり、支払処理そのものは変えない

## 6. 売上一覧（キャスト全員）`/cast/me/sales`

- 月を選ぶ（当月＋過去12ヶ月）。在籍中のキャスト全員を、合計の降順で並べる
- 列: キャスト名 / 来店 / 遠隔 / 合計（税込）
- 来店 = Airレジ取込（`AirRegiOrder`）で**カテゴリー名＝そのキャストの店舗別エアレジ名**の売上。3店舗を合算。赤伝はマイナス
- 遠隔 = remodri `groupBy=cast`（キャストコードで結ぶ）
- 当月は「Airレジは前日まで、遠隔は現在まで」と明記。自分の行を強調する
- 表示対象は `retired=false` のキャスト。10 分メモリキャッシュ

## 7. 管理画面「売上」タブ（店長）

- 店舗（東京/大阪/名古屋）と月を選ぶ
- 表: 営業日 × 来店（`AirRegiTransaction.totalAmount` に `transactionSign` を掛けた合計）× 遠隔（remodri `groupBy=date&storeCode=`）× 合計、月計
- グラフ: 積み上げ棒（来店＋遠隔）、営業日ごと。ライブラリは recharts
- 遠隔は**キャストの所属店舗**基準（伝票が立った店舗ではない）と画面に注記
- 当月は前日まで。Airレジの取り込み漏れがある日は表と凡例に印

## 8. 画面と導線

- ログイン後の遷移: `CAST` → `/cast/me`、それ以外は従来どおり
- `/cast/me`（ホーム）: 名前・所属店舗・「報酬」「売上一覧」への導線・ログアウト。客向けの機能（ポイント・予約・推し設定）は出さない
- NavBar: `CAST` のときは「マイページ」の代わりに「キャストページ」

## 9. データモデル変更

```
User.role            "CAST" を許容（文字列。制約は無い）
Cast.userId          String? @unique
CastInviteToken      id, castId, email, tokenHash @unique, expiresAt, usedAt?, createdAt
SalaryPeriod         finalizedAt DateTime?, finalizedByUserId String?
SalaryPeriodLog      id, periodId, action("finalize"|"unfinalize"), userId, createdAt
```

## 10. 受け入れ条件

- キャストAでログインして `/api/cast/rewards` を叩き、他キャストの castId をクエリに付けても A の値しか返らない
- CUSTOMER / ADMIN のセッションで `/cast/me` に入ると `/` に戻される。CAST のセッションで `/admin` に入ると `/` に戻される
- 確定済み期間に「計算実行＋DB保存」を送ると 409。確定解除後は保存できる。ログに2件残る
- 報酬画面の HTML に「時給」「労働時間」「基本給」「バック率」の文字列が出ない
- 売上タブの月計が、`AirRegiTransaction` を直接集計した値と一致する（テスト）
- 招待トークンは2回目に使うと拒否される

## 11. やらないこと（今回）

- ADMIN によるキャスト画面の代理閲覧
- キャスト自身によるプロフィール編集
- 報酬の PDF / CSV 出力
- 客（CUSTOMER）アカウントとキャストアカウントの統合
