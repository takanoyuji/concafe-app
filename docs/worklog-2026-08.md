## 1. 給与計算の「計算実行」が効かなくなっていた（`10102de`）

### 症状
管理画面で「計算実行」を押しても、結果もエラーも出ない。

### 原因
キャストの2テーブル統合(`bb2f14a`)で `Cast.hpName` → `Cast.name` に改名した際、
**別テーブルである `SalaryCastRecord` の `hpName` 列まで一括置換が及んでいた。**
schema 側は `hpName` のままなので、Prisma が実行時に落ちていた。

```
Unknown argument `name`. Did you mean `hpName`?
```

「計算結果をDBに保存」が初期値ONのため、計算実行が必ずこの経路を通って500。
クライアントの `res.json()` も例外になり、画面にエラーすら出なかった。

### なぜすり抜けたか
- Prisma のネスト create 入力は `XOR<>` 型で**余剰プロパティチェックが効かない**。`tsc` は通る
- 給与計算のテストが1件も無かった

### 対応
- `app/api/admin/salary/route.ts` を `hpName` に戻す
- `app/admin/page.tsx` の Cast 由来の `hpName` 参照7箇所を `name` に揃える
  （一覧の名前が空欄・名前の編集が保存されない・CSV取込で新規行が落ちる、も同時に解消）
- `HistoryCastRecord.hpName` は `SalaryCastRecord` の列なので**意図的に残し**、
  page.tsx と schema.prisma に再発防止コメントを入れた
- `tests/salary-save.test.ts` を追加。バグを戻すと落ちることを確認してから修正を戻した

教訓は `~/.claude/CLAUDE.md` と本リポジトリの `CLAUDE.md` に追記済み（`7081959`）。

## 2. 名古屋店の売上が全額0で計算された（`3d281c8`）

### 原因
エアレジの売上CSVが **UTF-8(BOM付き)** で書き出されていたのに、
`decodeShiftJIS()` が Shift-JIS 決め打ちで読んでいた。列名が化けて全項目 `undefined` → 0。

人件費CSVは `TextDecoder("utf-8")` が BOM を自動で落とすため無事に読めており、
**基本給だけ正しく出て売上とバックだけ0**という気づきにくい壊れ方をしていた。

### 対応
1. **文字コードの自動判定**（`decodeCsv`）— UTF-8 BOM があれば UTF-8、無ければ
   UTF-8 を `fatal` で試して失敗したら Shift-JIS。**この判定順でなければならない**
   （Shift-JIS の日本語は UTF-8 として不正になるが、逆は妥当な漢字に化けて検出できない）
2. **必須列の検証** — 列が欠けたら `CsvFormatError` を投げ、API は400で
   「欠けている列＋読み取れた列」を返す。0を返して計算を成功させない

実ファイルで検算: 名古屋 2026/8前半 税込売上 524,820円（遠隔 219,220 / 店内 305,600）。

## 5. 遠隔売上(remodri)の取り込み（`305b67f` `2076fa2`）

### 発覚した欠落
remodri は「遠隔ドリンク会計」で、**2026-08-16 にエアレジから移行**していた。
それ以降のエアレジCSVには `遠隔_` が載らないため、
**8月後半以降の遠隔売上が業績からもバックからも丸ごと抜けていた**（3店舗計 5,881,180円）。

### 連携方法
remodri 側に `GET /api/v1/sales/summary?groupBy=cast` が既にあり、
コメントに「xing-lang の給与・業績計算が叩くことを想定」と明記されていた。
`castCode` をキーに売上・原価・粗利を返す。赤伝のマイナス相殺と、
推し／もらったが別人の明細の50%折半は remodri 側で処理済み。

- 金額はすべて**税込**なので、エアレジの内税行と同じ扱いで
  粗利から `売上 × 0.1` を引いてからキャストの粗利に加算（＝バックに乗る）
- **移行前の期間は remodri が0件を返す**ので、7月以前を再計算しても数字は変わらない。
  期間で切り替える設定は持たない
- 取り込みに失敗したら**502で止める**（0件として続行すると遠隔が抜けた給与が確定する）

### 帰属のルール（2026-09-01 決定）
伝票がどの店舗で立ったかは見ず、**キャスト本人の所属店舗**の売上・人件費に計上する。
遠隔は店舗をまたいで接客するため、伝票ベースだと約175,420円のバックが宙に浮いていた。

```
伝票ベース     東京 2,335,620 / 大阪 3,167,680 / 名古屋 377,880
所属店舗ベース  東京 2,072,640 / 大阪 3,356,885 / 名古屋 451,655
合計はどちらも 5,881,180（過不足なし・所属店舗が無いキャストは0人）
```

その店舗のエアレジ名が無くても、遠隔売上があるキャストは対象に含める
（遠隔専任のキャストがどの店舗の計算にも入らない状態を防ぐ。実例: 伊藤さん）。

### 期間パラメータの変更
remodri の取得に期間が必要なため `year/month/half` を常に送るようにし、
**DBに保存するかどうかは `save` フラグで明示的に**受け取るようにした
（従来は「期間が来たら保存する」だったため、期間を送ると必ず保存されていた）。

全店舗合算の画面に**人件費サマリー**（キャスト給与 / その他人件費 / 人件費合計 /
売上比率）と店舗ごとの内訳を追加。

（2026/07 は欠けなし、2026/08 は3店舗とも後半が未計算）。
