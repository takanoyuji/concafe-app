## 1. 要件をどう決めたか

最初に3案を出した。

| 案 | 仕組み | 開発量 |
|---|---|---|
| A（当初の推奨） | 完了画面に予約番号と照会URLを出し、予約番号＋電話番号で開く | 小 |
| B | 既存の会員（`User`）に予約を紐づけ、マイページに一覧 | 中 |
| C | LINE公式の自動通知 | 大・従量課金 |

Aを推奨したのは「会員登録は不要」（要件書 4-1）を崩さないため。
高野の判断は **B寄り**で、次の4点が確定した（2026-09-12）。

1. お客様向けの状態の言葉は **申請中 / 予約確定 / お受けできませんでした / キャンセル済み** の4つ。来店済み・無断キャンセルは店舗の内部記録なので見せず「予約確定」のまま
2. 見られるのは**会員登録した人だけ**（電話番号だけの本人確認は弱い）
3. **過去分まで並べる**
4. 結果は**メールで自動通知**する

その後、**予約そのものも会員登録・ログイン必須**に変更（4-1 の「登録不要」を撤回）。
理由: 通知先を本人のメールアドレスに固定でき、フォームからメール欄を消せる。ログインできる会員はメール認証済み。

## 2. 実装

### データ
- `Reservation` に `email`（通知先）と `userId`（会員ID）を追加。既存行は空文字。関係は張らない（会員を消しても予約の記録は残す）
- migration `20260912000000_add_reservation_email_user`（列2本＋index2本）

### お客様側
- `/reserve` は server component で入口を分け、未ログインなら理由とログイン/会員登録の導線（`/auth/login?next=/reserve`）。フォーム本体は `ReserveForm.tsx`
- フォームにメール欄は無い。会員のアドレスを「ご連絡先」として表示だけ。名前はプロフィールのニックネームが初期値
- `/api/reserve` はログイン必須（401）。**メールアドレスと会員IDはサーバー側で会員情報から取る**。フォームに `email` を混ぜて送っても無視される
- `/me/reservations` を新設。来店日の新しい順、`CUSTOMER_STATUS_LABEL` の4表示。マイページに「ご予約（申請中 N件）」カード
- 表示条件は `customerReservationWhere()`: `userId` 一致、または**メール認証済み**会員のメールアドレス一致（手入力の予約にメールを入れておけば本人にも出る）。認証済み条件は、他人のメールで登録して氏名・電話番号を覗く経路を塞ぐため
- ログイン画面に `?next=` を追加。サイト内パス（`/` 始まり・`//` は不可）だけ受ける

### 通知
- `lib/email.ts` に受付・確定・お断りの3通（HTML＋text）。既存の Resend を流用
- 受付は `/api/reserve`、確定/お断りは管理APIの `PATCH` で送る。VISITED / NO_SHOW / CANCELED では送らない
- **送信失敗で予約や状態変更を失敗させない。** try/catch でログに残して通す。LINEでの手動連絡は続ける前提
- 管理画面の手入力はメール任意・自動メールなし（店舗が直接話しているため）

## 3. 検証

- テスト 151件（予約まわりに16件追加: 未ログイン401 / 会員のアドレスで保存 / メール送信の有無 / 送信失敗時の挙動 / 表示条件 / 他会員の不可視）
- 別ポートの本番ビルドで通し確認: 未ログインの `/reserve` に導線ブロックのみ → 未ログインPOST 401 → 会員でログイン → フォームにアドレス・ニックネームが入る → `email: "attacker@example.com"` を混ぜてPOSTしても会員のアドレスで保存・`userId` 付き → マイページに表示
- **Resend で実送信を確認。** `delivered@resend.dev` 宛に受付・確定メールが message_id 付きで成功。`example.com` 宛が Resend に拒否されたケースでも予約は 201 で成立（失敗を握る設計が効いている）
- 画面はログインCookieを注入する小さなプロキシ（node, 20行）を挟んでヘッドレスChromeで撮った。JWT Cookie 方式なのでDBにセッション行を入れる必要はない

## 6. 学び

- **「誰が見られるか」を先に決めると、認証の作りが決まる。** 照会ページ（予約番号＋電話）は会員登録不要の前提から出た案で、会員限定と決まった瞬間に不要になった。案の前提を並べて出したので、1往復で切り替えられた
