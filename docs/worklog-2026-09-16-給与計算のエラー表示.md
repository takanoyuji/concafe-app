## 症状

管理画面の給与計算で「計算実行」を押しても何も出ない、との報告。

## 調べたこと

nginx のアクセスログに 9/16 04:57〜04:58 JST、東京店から `POST /api/admin/salary` が6回、**全て 400**。
400 の本体はサーバーに残らないので、応答バイト数（chunked 枝葉込みで 322 / 214）から候補文言を総当たりで照合し、
次の2つと**完全一致**した。

1. `tokyo の 20260916〜20260930 で、取り込めていない営業日が 15 日あります`（2回）
2. `tokyo の 20260901〜20260915 で、取り込めていない営業日が 1 日あります: 20260915`（4回）

つまり計算は壊れておらず、取り込み漏れガードが正しく止めていた。見えなかっただけ。

重なった要因:
- 期間の既定が「今日を含む期間」で、16日に開くと未来の「後半」になる（`page.tsx` の `salaryHalf` 初期値）
- 前日分の取り込みは毎朝 08:00 JST の cron（`airregi-fetch.sh` は前日まで）。9/15 分は 9/16 08:02 に初めて入った。
  04:57 の操作では前半を選んでも通らない。管理画面の「取り込み」は取得済みJSONを入れ直すだけで、Airレジからは固定IPのcronしか取れない
- `flash()` の表示先がページ最上部で3秒だけ。給与タブまでスクロールしていると視界の外で出て消える。
  `res.json()` が失敗する応答（500・nginx）は catch が無く無言（2026-08-14 と同じ構造）

## 直したこと（仕様は変えていない）

- 計算実行ボタンの直下に、次の計算まで消えないエラー枠（`data-testid="salary-error"`）
- `res.json()` 失敗と通信失敗も理由を出す
- 前日以降の営業日が欠けているときは「毎朝8時に自動で取り込まれます」の案内に切り替える（`lib/airregiSales.ts`）。テスト1本追加

期間の既定値は変えていない（高野の判断: 今の仕様のままエラーだけ見せる）。

## 確認

- `tsc --noEmit` OK / vitest 152件 OK
- 本番DBのコピーで新イメージを別ポート起動し、ADMIN セッションで API を叩いて確認:
  2026/09 後半 → 400 + 新しい案内文 / 2026/09 前半 → 200 / 2026/08 後半 → 200
- 本番反映後: トップ 200、未認証 POST 403、クライアントJSとサーバーチャンクに新文言が入っていることを grep で確認
